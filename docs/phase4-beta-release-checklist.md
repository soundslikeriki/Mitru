# Mitru Phase 4 ベータ公開チェックリスト

Phase 4では「長く使える業務アプリ」として、見た目の統一、入力の迷いにくさ、壊れにくい配布準備を優先して確認する。

## 1. UI/UX最終確認

- [ ] ダッシュボード、案件一覧、案件詳細、積算、見積書、請求書、納品書、注文書、顧客管理、マスタ設定、アプリ設定をライトモードで確認する
- [ ] 同じ主要画面をダークモードでも確認する
- [ ] 粗利率の警告基準が全画面で統一されていることを確認する
  - 30%未満: 黄
  - 25%未満: 赤
- [ ] カード、テーブル、ボタン、入力欄の余白が極端に詰まっていないことを確認する
- [ ] ステータスバッジ、粗利バッジ、警告表示の文字がライトモードで読みにくくないことを確認する

## 2. 入力・操作性

- [ ] 新規案件作成、顧客登録、積算行追加、書類作成の主要フォームで入力しやすさを確認する
- [ ] 必須項目のエラー表示が日本語で統一されていることを確認する
- [ ] 数値入力、金額入力、電話番号、郵便番号の補助入力が意図通り動くことを確認する
- [ ] 行削除、顧客削除、案件削除、書類削除で確認ダイアログが表示されることを確認する
- [ ] 保存・更新・削除後にトースト通知が出ることを確認する

## 3. レスポンシブ確認

- [ ] 1280px幅で主要画面の横スクロールが必要最小限になっていることを確認する
- [ ] タブレット幅でサイドバー、ヘッダー、テーブル、カードが破綻しないことを確認する
- [ ] スマホ幅でタブ、フォーム、ボタンが押しやすいサイズを維持していることを確認する
- [ ] 積算テーブルは横スクロールで全列を確認できることを確認する

## 4. 書類・PDF

- [ ] 見積書、請求書、納品書、注文書のプレビューを確認する
- [ ] PDF出力でロゴ、社判、顧客情報、会社情報、明細、合計が崩れないことを確認する
- [ ] 明細が10行を超えた場合の改ページを確認する
- [ ] 印刷時にサイドバーや編集UIが出力されないことを確認する
- [ ] 書類番号設定が新規書類に反映されることを確認する

## 5. ローカルデータ・バックアップ

- [ ] リロード後も案件、顧客、積算、書類、設定が保持されることを確認する
- [ ] localStorageの破損時にアプリが真っ白にならず復旧できることを確認する
- [ ] データ出力から全案件CSVを出力できることを確認する
- [ ] 見積書・請求書の一括PDF出力が実行できることを確認する

## 6. パフォーマンス・安定性

- [ ] 50件以上の積算行でも入力が極端に重くならないことを確認する
- [ ] マスタ一覧、顧客一覧、案件一覧の検索・フィルターが軽快に動くことを確認する
- [ ] コンソールに重大なエラーが出ていないことを確認する
- [ ] `npm run build` が成功することを確認する
- [ ] Tauri本番ビルドが成功することを確認する

## 7. ベータ公開前の判断

- [ ] 既知の未実装機能をREADMEまたはリリースメモに明記する
- [ ] ベータ版の対象ユーザーと想定利用範囲を明確にする
- [ ] 重要データのバックアップ手順を案内する
- [ ] 初回起動オンボーディングの内容が現在の機能と一致していることを確認する
- [ ] アプリ名、バージョン、アイコン、配布ファイル名がMitruとして統一されていることを確認する

## 8. Phase 4 最終追加確認

- [ ] 積算 → 見積 → 請求締め → 入金 → 発注 → 支払 → レポートの一連の流れを確認する
- [ ] 0円請求、法定福利費0%、数量0、単価0でも画面が落ちないことを確認する
- [ ] 80件以上の案件、400件以上の積算行を想定した表示確認を行う
- [ ] READMEとCHANGELOGが `0.9.6-beta` の内容になっていることを確認する
- [ ] 初回起動時にサンプルデータ読み込みが推奨導線として十分に目立つことを確認する
